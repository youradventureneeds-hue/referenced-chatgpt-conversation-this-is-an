# Job categories

The public `/jobs` board filters reviewed, published vacancies by one primary category, together with country, work type, keyword search, and visa sponsorship. Categories describe the job function; seasonal, volunteer, internship, and full-time remain independent work types. The JSON `/api/jobs` endpoint accepts the same filters, including `category`, and rejects invalid category or work-type values. Category counts in the filter reflect the other active filters.

`lib/job-categories.mjs` defines Outdoor education, Camps & youth programs, Trekking & trip guiding, Adventure instruction, Water sports & diving, Conservation & fieldwork, Management & leadership, Operations & support, and Other outdoor roles. Automatic classification uses the role's title, not employer boilerplate. Ambiguous titles remain Other outdoor roles for owner review.

Employers can choose a category or leave Automatic selected. The private intake review form can override it before publication. `/admin/job-categories`, linked from Administration, allows the owner to change an existing published vacancy or restore automatic categorization. Every mutation requires owner authentication and a same-origin request. A manual category is stored with `categoryManual=true` and survives subsequent official-scraper refreshes. New official-source vacancies are categorized automatically, and reviewed Instagram vacancies are categorized when the owner publishes them.

Apply `prisma/migrations/20261102150000_job_categories/migration.sql` before deploying the new generated client. Backfill existing jobs using `inferJobCategory(title)`, updating only rows where `categoryManual=false`. The change adds metadata and an index without changing vacancy content, publication status, source links, or organization membership. A job's category can be corrected through the admin portal.

Run `pnpm test:jobs` for the scraper and classification regressions. The account integration suite covers combined public filters, unpublished-job exclusion, employer suggestions, reviewer overrides, and protected category administration. For a focused database check, generate `work/employer-check-schema.sql`, set `EMPLOYER_ALLOW_ISOLATED_DB_TEST=1`, then run `node --import ./scripts/testing/employer-loader.mjs scripts/jobCategories.integration.mjs`. It creates and removes only its own temporary schema.
